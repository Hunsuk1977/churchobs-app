## CMake 연결 수정 · 2026-10-18

Mac 사용자 로그에서 `Subdirectories may not be created during deferred execution` 오류를 확인했습니다. DEFER 훅을 제거하고 upstream 설정 마지막에 일반 add_subdirectory 호출을 추가하도록 변경했습니다. Linux CMake 3.30.9 회귀 테스트 4개에서 이전 오류 재현, 수정 후 설정/타깃 생성, 반복 적용, 사용자 변경 보호를 확인했습니다. 이 검사는 실제 macOS 라이브러리의 구성·빌드 성공을 의미하지 않습니다.

## 런타임 의존성 수정 · 2026-10-18

사용자 Mac에서 빌드가 진행된 뒤, 테스트 실행 시 FFmpeg libavformat의 하위 의존성 libmbedcrypto.dylib 누락으로 dyld가 중단한 로그를 확인했습니다. Mach-O LC_LOAD_DYLIB/LC_RPATH를 재귀적으로 검사하고, 고정된 OBS prebuilt lib 디렉터리에서 필요한 dylib만 복사하는 패키징 단계를 추가했습니다. 앱/플러그인/프레임워크/헬퍼를 검사하고 내부부터 개발용 서명을 다시 적용합니다. 그래프·파서 테스트 8개는 모의 Mach-O 메타데이터로 통과했으며 실제 Mac otool/install_name_tool/codesign 실행과 앱 재실행은 사용자 Mac에서 확인해야 합니다.

## 종료 중 충돌 수정 · 2026-10-18

사용자 Mac에서 녹화 151프레임 및 파일 생성은 확인됐지만, 엔진 종료 중 segmentation fault가 발생했습니다. 기존 테스트가 종료 전 PASS를 출력한 것은 오류였습니다. OBS 32의 main canvas PROGRAM 플래그에는 SCENE_REF가 포함되므로 앱이 scene_release만 호출하면 내부 참조가 남습니다. scene source_remove, 카메라 항목/필터 분리, 소스 release, 파괴 큐 drain을 분리한 정리 함수를 추가했습니다. 실제 OBS 헤더로 컴파일한 C 참조 모델 테스트가 이전 참조 잔류 및 수정 후 정리 순서를 확인했습니다. 셸 테스트 2개로 프로세스 exit 139이면 PASS를 표시하지 않으며 exit 0일 때만 표시함을 확인했습니다. 실제 Mac 재빌드 및 정상 종료는 재검증이 필요합니다.

## 피부 보정 무변화 대응 · 2026-10-18

사용자 Mac에서 엔진·기기·녹화·정상 종료가 확인됐으나 피부 보정은 차이가 없다는 피드백을 받았습니다. 원본 필터의 고정 1.5픽셀 반경/낮은 강도와 비-sRGB 입력 처리 생략을 개선했습니다. 출력이 SDR인 앱이므로 OBS의 SDR intermediate 렌더 경로로 입력을 변환하고, 출력 크기에 비례한 반경·더 넓은 피부톤 마스크·강도 조정 및 약한 피부 밝기 보정을 적용했습니다. 실제 원인 확정이나 화질 검증은 아직 아닙니다.

UI에 좌우 비교 및 실제 필터 처리 상태를 추가했습니다. 녹화 시작 시 비교 모드는 끕니다. 생성 테스트 소스에 피부색의 미세 텍스처를 넣고, GPU 필터 처리 후 실제 NV12 출력 프레임을 받아 보정 끔/강하게의 luma 차이가 0.20 이상인지 검사하도록 했습니다. 이 GPU 검사는 Mac에서 실행해야 하며, 통과하더라도 실제 얼굴의 자연스러움이나 모든 피부색의 품질을 보장하지 않습니다. 변경된 C 파일의 실제 OBS 헤더 구문 검사는 통과했습니다.


## 얼굴 보정 첫 버전 · 2026-10-18

사용자가 이전 피부 보정의 차이를 실제 Mac 카메라에서 확인했습니다. 새 버전은 Apple Vision을 추가하며 이전 버전의 실행 성공이 새 버전의 검증을 대신하지 않습니다.

- 구현: 카메라 원본 async filter_video 경로에서 최대 10Hz로 480px 폭 BGRA 축소, 별도 직렬 큐에서 Vision 얼굴 특징점 분석. 프레임을 큐에 쌓지 않고 분석 중인 프레임은 건너뜁니다. 검출 결과만 mutex로 공유하며 GPU 작업은 렌더 스레드에 유지합니다. NV12/BGRA를 포함한 OBS scaler 지원 입력을 사용합니다.
- 구현: 얼굴 영역 제한 피부 처리, 눈·눈썹·입 보호, 볼/턱선의 약한 역매핑, 눈 확대 및 국소 선명도, 기존 눈썹 대비. 전체 강도와 네 항목 개별 조절, 좌우 비교, 녹화 전 비교 해제.
- 구현: 추적 결과 노후화 후 0.5초 내 gain 0, 렌더 프레임마다 시간 기반 보간. 큰 얼굴 위치 변경 시 기존 보정을 먼저 줄이고 새 얼굴로 전환. 고개 yaw/roll이 클 때 보정을 줄임.
- Linux 통과: 실제 OBS 헤더로 C 필터·보간·테스트 소스·소스 수명 코드 구문 검사. 보간/만료/30·60fps 독립성/재획득/급격한 위치 변경의 실행 테스트. 기존 CMake·런타임·스모크 래퍼 회귀 검사 14개 통과.
- Mac에 추가한 자동 검사(현재 환경에서는 실행 불가): 실제 NV12/BGRA 변환 및 Vision 무얼굴 요청, 합성 얼굴 좌표로 네 조절을 각각 켰을 때 실제 출력 Y 픽셀 변화, 얼굴 좌표가 없으면 원본 출력 복귀, 녹화·정상 종료. 합성 좌표는 생성 테스트 소스에서만 허용하며 실제 카메라에서는 사용할 수 없습니다.
- 미검증: 새 Objective-C++/Apple SDK 컴파일·링크, GPU effect 컴파일, 실제 카메라의 얼굴 검출·정렬·좌우 반전, 자연스러움, 다인 화면에서 대상 전환, 안경/가림/피부색/조명, CPU/GPU 사용량·지연. 사용자 Mac에서 빌드와 실제 동작 확인이 필요합니다.

배포용 적용 스크립트는 공백이 포함된 임시 폴더에서 빌드/실행만 모의 처리하여 두 번 적용했습니다. 23개 파일의 바이트 일치와 최초 백업 보존을 확인했습니다. 이는 실제 Mac 빌드 성공을 의미하지 않습니다. 셸 구문과 Info.plist XML 검사도 통과했습니다.

Mac 첫 컴파일에서 normalizedPoints가 CGPoint 배열인 것을 vector_float2로 선언한 오류가 확인됐습니다. 실제 SDK 진단에 따라 const CGPoint *로 수정했습니다. 재빌드와 실행 검증은 사용자 Mac에서 이어갑니다.

Mac에서 EngineCore의 필터 포인터 skin과 보정 강도 double skin 중복으로 다섯 컴파일 진단이 확인됐습니다. 강도는 skinAmount로 변경하고 설정 전달·프리셋·개별 조절·검사 복원 참조를 함께 수정했습니다. 실제 EngineCore 선언과 네 경로의 C++ 문장을 추출해 실제 OBS 헤더로 g++17 구문 검사를 수행했습니다. 이전 버전에서 중복/자료형 오류를 재현했고 수정본은 통과했습니다. 이는 AppKit/Vision을 포함한 전체 Mac 빌드 검사를 대신하지 않습니다.

사용자 화면에서 얼굴 분석 실패·보정 대기가 확인됐습니다. 고정 OBS 소스에서 VIDEO_SCALE_BILINEAR는 SWS_BILINEAR | SWS_AREA로 변환되며 FFmpeg가 두 알고리즘 플래그를 거부합니다. 로컬 libswscale에서 NV12/BGRA 모두 기존 플래그로 초기화 실패, FAST_BILINEAR로 초기화 성공을 재현했습니다. 앱 요청만 VIDEO_SCALE_FAST_BILINEAR로 변경했고 vendor는 변경하지 않았습니다. 사용자 Mac의 재빌드·Vision·실제 얼굴 추적은 추가 확인이 필요합니다.


## 영상 변환 실패 최종 대응 · 2026-10-18

스크린샷에서 사용자가 EOS Webcam Utility를 연결하고 모든 강도를 올렸지만 `얼굴 분석 실패 · 보정 대기`인 것을 확인했습니다. 회색 단계 실패를 단순한 조절값 문제로 처리하지 않았습니다.

확정한 코드 결함은 요청한 OBS VIDEO_SCALE_BILINEAR가 고정 upstream 소스에서 SWS_BILINEAR | SWS_AREA로 변환되고, FFmpeg가 알고리즘 두 개를 함께 선택하는 것을 거부하는 것입니다. 로컬 libswscale에서 원래 조합이 오류로 끝나는 것을 재현했습니다. FAST_BILINEAR 한 개로 변경한 뒤 NV12, BGRA, UYVY422, YUYV422 각각 1280×720 → BGRA 480×270 실제 픽셀 변환을 실행해 출력 높이·알파·균일 색을 확인했습니다. FFmpeg 8.1 공식 소스도 동일한 혼합 플래그 거부 조건을 확인했습니다. 사용자 Mac에서는 아직 수정본을 실행하지 않았으므로 이것만으로 모든 실패 원인이 해소됐다고 단정하지 않습니다.

추가 구현:

- Vision용 BGRA를 불투명하게 만들고 frame.flip이 있으면 분석 전에 행을 뒤집어, 검출 좌표와 OBS 표시 방향을 일치시켰습니다. 가짜 좌표로 보정을 켜는 대체 동작은 추가하지 않았습니다.
- 변환기/버퍼/픽셀 변환/Vision/오래된 결과/큰 고개 회전을 구분하는 상태와 오류 코드. 2초 간격 상태 로그. 얼굴·눈 위치 표시를 켤 수 있으며 녹화 시작 시 비교와 위치 표시는 끕니다.
- 보정 값과 마지막 장치의 NSUserDefaults 저장. 비교·위치 표시는 복원하지 않습니다.
- 카메라와 같은 async 원본 프레임 경로를 사용하는 공개 도메인 NASA 얼굴 사진 검사 소스. Mac 테스트는 실제 Vision 검출 횟수, 렌더 gain, GPU 출력 픽셀 차이까지 확인합니다. 실제 Mac에서 실행해야 하는 검사이며 이 환경에서 통과했다고 주장하지 않습니다.

로컬 확인:

- Python 회귀 검사 17개 통과. 그 중 변환 검사는 실제 libswscale로 수행했고 원래 충돌도 재현했습니다.
- BGRA 행 반전·알파·패딩·잘못된 치수, 시간 기반 좌표 보간·추적 만료·30/60fps·재획득·급격한 위치 변경을 실제 C 실행 파일로 검사했습니다. AddressSanitizer/UndefinedBehaviorSanitizer에서 통과했습니다. 이 실행 환경에서는 LeakSanitizer의 ptrace 제한 때문에 leak 검사는 제외했습니다. 두 함수에는 동적 할당이 없습니다.
- 새 C 소스들을 고정된 OBS 헤더로 -Wall -Wextra -Werror 구문 검사했습니다.
- 실제 EngineCore와 보정 설정/프리셋/개별 조절/복원 C++ 문장을 추출한 자료형 검사에서 이전 이름 충돌은 재현되고 수정본은 통과했습니다. 전체 Objective-C++/Apple SDK 컴파일을 대체하지 않습니다.
- 소스 문자열·셸 문법·Info.plist·얼굴 fixture 크기 검사를 통과했습니다. upstream 5,537파일 무결성은 유지합니다.

남은 실제 장치 확인: 새 버전 전체 Mac 빌드와 링크, Vision/GPU 통합 검사, EOS Webcam Utility와 내장 카메라의 실제 얼굴 추적·효과·지연, 마이크와 긴 녹화·송출 안정성. 이 환경은 Linux이며 사용자 Mac에 원격 접근할 수 없습니다.

공식 변환 규칙: https://www.ffmpeg.org/doxygen/8.1/libswscale_2utils_8c_source.html

## 중앙 크롭 비교 · 2026-10-19

한 얼굴의 좌/우를 나누던 비교를 동일 프레임의 중앙 50% 폭을 좌우 패널에 각각 표시하는 방식으로 변경했습니다. 양쪽 패널은 같은 UV를 사용하고 세로 좌표와 가로 스케일을 유지합니다. 왼쪽은 모든 보정과 진단 표시를 우회하며 오른쪽만 보정합니다. 강도 0과 얼굴 미검출 상태에서도 비교 크롭을 유지하고, 비교 해제 시 전체 UV로 복귀합니다. 녹화 시작 시 비교 해제 동작은 유지합니다. 중앙에 얼굴을 놓고 비교하세요.

로컬 소스·셸·C 구문과 좌표 대응을 확인했습니다. 새 GPU shader 컴파일과 Mac 화면 확인은 실제 Mac에서 실행해야 합니다.

Mac GPU 자동 검사에 보정 강도 0일 때 양쪽 패널의 대응 Y 픽셀이 동일한지 확인하는 항목을 추가했습니다. 여러 색 패널로 된 기존 테스트 영상에서 이전 좌우 분할은 실패하게 됩니다. 이 새 검사는 실제 Mac 실행 대기 상태입니다.


## YouTube Preview 0.4.0 · 2026-10-19 UTC

구현: 고정 장면 5개(안내 카드, 카메라+가사, 카메라+제목, 본문/PNG·JPEG, 마침 카드), 문구/이미지 경로 저장. 프런트엔드와 녹화/송출은 같은 OBS 장면을 사용. Google Desktop OAuth PKCE+state+loopback, Python 표준 라이브러리 API worker와 Cocoa Keychain 저장, 예약 예배 선택·신규 생성·RTMPS 준비/송출·live/complete 전환, 상태 확인과 종료 보호. 신규 예배는 일부 공개 기본값이며 공개 범위·아동용 여부를 지정. API POST는 불확실한 실패 후 자동 재시도하지 않음. 기존 자동 시작/종료 예약은 거부. 실제 송출에는 obs-outputs와 rtmp-services를 추가하며 upstream은 수정하지 않음.

Linux 로컬 Python 회귀 총 32개 통과(기존 17개 + YouTube 14개). YouTube 검사에서 OAuth callback은 실제 localhost HTTP를 사용하고 Google 요청만 모의 처리함. 기존 source literals/shell/plist/fixture와 C helper 검사 통과. EngineCore와 기존 설정 경로의 실제 OBS 헤더 C++ 자료형 검사 통과. 새 송출 연결·구성/해제 함수도 OBS 헤더로 추출 C++ 구문 검사하며, 이는 Foundation/AppKit/전체 Objective-C++ 컴파일을 대체하지 않음.

Mac 검사 추가: 실제 RTMPS 서비스·출력 생성(네트워크 연결 없음)과 5개 장면 간 GPU 출력 변화. **아직 실행 대기**. Mac 전체 컴파일, 새 모듈 번들/서명, 카드 문자 방향·알파 합성·레이아웃, 실제 Keychain·Google 승인·Live API·RTMPS 송출·장시간 예배는 검증하지 못함. OAuth 설정/사용 안내는 YOUTUBE-SETUP.md 참조.

최종 적용 파일 검사: 57개 payload의 해시/설치 바이트, 공백 경로, 반복 적용의 최초 백업 보존, 앱 실행 중 보호, 빌드·스모크 실패 시 앱 실행 차단 통과. 이 검사에서 Mac 빌드/실행 단계는 모의 처리했습니다. 새 백업 위치는 backups/youtube-preview-040입니다. upstream 5,537파일 hash 일치 유지.
